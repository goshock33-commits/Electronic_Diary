# 待办服务卡片纸片悬浮设计

## 背景与问题

待办服务卡片当前在外层底卡和内层列表上同时使用 `form_card_bg`。内层只有半径 4、向下 2vp、低透明度的阴影，因此两层在亮色和深色桌面上都容易融为一体，待办项缺少“悬浮在底卡上”的空间层级。

实际生效页面是 `entry/src/main/ets/formpages/TodoFormPage.ets`。该文件已有真实数据首帧解析和整卡点击跳转等未提交改动，本次必须保留。

## 目标

- 采用已确认的 B“纸片悬浮”方向，让待办列表作为一张纸片明显浮于底卡之上。
- 卡片最多显示 3 条待办，防止内容拉长或挤压底部进度条。
- 总数超过 3 条时显示“还有 N 项”，提示用户点击服务卡片查看完整列表。
- 同步优化标题、完成计数、分割线、进度条、留白和圆角的一致性。
- 保留真实数据、服务卡片更新、完成状态和整卡点击跳转逻辑。
- 浅色与深色模式均具有清晰层级和足够对比度。

## 视觉设计

### 底卡

外层底卡使用独立的柔和纸灰资源，不再与悬浮纸片共用背景色。浅色模式采用暖灰白，深色模式采用炭灰；保留 16vp 外圆角，作为安静的承托层。

### 悬浮纸片

内层列表使用独立表面色：浅色为纯白，深色为比底卡更亮的灰。纸片整体向上偏移约 6～8vp，使用 12vp 圆角、细描边和更明显的向下投影。阴影负责高度，描边负责亮色桌面和高对比场景下的边缘稳定性。

多条待办共用一张纸片，内部使用轻量分割线，不为每一条重复添加阴影，避免 2×4 服务卡片过于拥挤。

### 信息层级

- 日期保留为主标题。
- 完成数 `已完成/总数` 改为紧凑徽章，和标题形成主次层级。
- 每条待办保留完成图标、单行标题和完成删除线。
- 最多显示 3 条；`totalCount > 3` 时在纸片底部显示“还有 N 项”。
- 进度条增加可见轨道，完成色继续使用现有强调绿。

## 数据与交互

`TodoFormPage.parseTodos()` 继续只返回前 3 条。溢出数使用 `totalCount - 3` 计算，仅在结果大于 0 时显示。所有展示数据继续来自 `TodoFormAbility` 注入的 `dateStr`、`totalCount`、`completedCount` 和 `todos`。

整卡 `postCardAction` 跳转保持不变。视觉容器不增加独立点击行为，避免服务卡片事件冲突。

## 空态与异常

- 无待办时不显示伪造条目或溢出提示；悬浮纸片保留简洁空态文案。
- JSON 解析和服务卡片数据异常沿用现有处理范围，本次不重构数据层。
- 颜色资源必须同时在 `base` 和 `dark` 目录定义，防止自动深色模式退回错误颜色。

## 测试与验收

- 0、1、2、3 条待办时布局不溢出，悬浮纸片与底卡边界清晰。
- 4 条及以上待办只展示前 3 条，并正确显示“还有 N 项”。
- 浅色与深色资源均存在，底卡、纸片、描边和阴影形成明确层级。
- 完成图标、删除线、完成徽章和进度条数据正确。
- 整卡点击仍跳转到待办页。
- Release HAP 构建通过；安装到本地设备并刷新服务卡片后，截图验证层级、间距和裁剪。

## 范围

本次只修改待办服务卡片 UI、必要的颜色资源与回归测试，不调整待办业务逻辑，也不改造其他服务卡片。
